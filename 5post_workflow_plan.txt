================================================================================
ПОЛНАЯ АРХИТЕКТУРНАЯ СХЕМА И ПЛАН РАБОТЫ:
САЙТ BOYFORGE -> ОПЛАТА -> 5POST API -> GOOGLE ТАБЛИЦА -> СКЛАД/МЕНЕДЖЕР
================================================================================
Файл: 5post_workflow_plan.txt
Версия: 1.0 (Production Blueprint)
Цель: Полная автоматизация цикла от оформления заказа покупателем до передачи
      готовой посылки с официальной маркировкой 5Post в доставку.
================================================================================

2. ПОШАГОВАЯ ДЕТАЛИЗАЦИЯ ИНТЕГРАЦИИ И API
--------------------------------------------------------------------------------

ШАГ 1: Клиентский интерфейс (Сайт)
- Покупатель заполняет форму:
  * ФИО: Обязательно 2-3 слова (Фамилия Имя [Отчество]). Требование регламента выдачи 5Post.
  * Телефон: Номер РФ (+7 999 000-00-00), на него 5Post отправляет SMS с кодом.
  * Telegram: Контакт для связи менеджера (@username).
  * Точка выдачи: Выбирается на интерактивной карте (сохраняются ID, Адрес, Тип, Партнер).
- Нажатие кнопки «Оплатить»: Открытие виджета CloudPayments.

ШАГ 2: Фиксация оплаты (CloudPayments)
- Покупатель вводит данные карты, подтверждает через 3D-Secure или СБП.
- CloudPayments возвращает статус `Completed` с номером транзакции `TransactionId`.
- Покупатель видит окно успешной оплаты с итоговыми данными заказа.

ШАГ 3: Создание заказа в API 5Post (Серверная часть)
- Бэкенд BOYFORGE отправляет запрос к API 5Post:
  URL: https://api-omni.x5.ru/order-management-service/v1/orders
  Заголовки:
    Authorization: Bearer <5POST_JWT_TOKEN>
    Content-Type: application/json
  Тело запроса (Payload):
  {
    "senderOrderId": "BF-92841X",
    "deliveryType": "STANDARD",
    "partner": "5POST",
    "warehouseId": "WH-PENZA-MAIN",              // ID склада отгрузки BOYFORGE
    "pickupPointId": "5P-PENZA-380541214",       // Выбранный клиентом ПВЗ
    "receiver": {
      "name": "Иванов Иван Иванович",
      "phone": "+79991234567",
      "email": "order-BF-92841X@boyforge.ru"
    },
    "cost": {
      "declaredValue": 3200,                     // Объявленная ценность
      "deliveryCost": 0                          // Доставка включена
    },
    "cargoPlaces": [
      {
        "cargoPlaceId": "BF-92841X-1",
        "weight": 350,                           // Вес в граммах
        "dimensions": { "length": 30, "width": 25, "height": 5 } // Габариты см
      }
    ]
  }

- Ответ от 5Post:
  {
    "orderId": "5P-ORD-77889900",
    "cargoPlaces": [
      {
        "cargoPlaceId": "BF-92841X-1",
        "barcode": "79201234567890"               // Штрихкод грузоместа
      }
    ],
    "labelUrl": "https://api-omni.x5.ru/labels/BF-92841X.pdf",
    "status": "CREATED"
  }

ШАГ 4: Передача полного пакета данных в Google Таблицу
- Бэкенд формирует финальный payload и передает его в Google Apps Script:
  {
    "date": "07.09.2026 17:05:00",
    "orderId": "BF-92841X",
    "fivepostOrderId": "5P-ORD-77889900",
    "fivepostBarcode": "79201234567890",
    "fivepostLabelUrl": "https://api-omni.x5.ru/labels/BF-92841X.pdf",
    "productName": "Футболка «Братья Святославичи»",
    "size": "M",
    "gender": "Мужской",
    "price": "3 200 ₽",
    "fio": "Иванов Иван Иванович",
    "phone": "+7 (999) 123-45-67",
    "tg": "@ivan_test",
    "pointAddress": "г. Пенза, проспект Победы, д. 138 (Постамат 5Post)",
    "paymentTxId": "CloudPayments #999888777",
    "status": "Оплачен, готов к упаковке"
  }

ШАГ 5: Регламент работы менеджера и склада
1. Менеджер открывает Google Таблицу и видит новые строки со статусом «Оплачен, готов к упаковке».
2. По ссылке `fivepostLabelUrl` менеджер открывает и распечатывает термоэтикетку (формат 100x150 мм или 58x40 мм).
3. Работник склада берет со стеллажа нужный размер товара (например, Размер M), проверяет качество.
4. Вкладывает товар в фирменный zip-пакет BOYFORGE, прикладывает брендированные стикеры/открытку.
5. Наклеивает распечатанную этикетку 5Post с ШК на лицевую сторону упаковки.
6. В Google Таблице меняет статус на «Упакован, передан в 5Post».
7. Партия передается на приемку 5Post. С этого момента посылка автоматически трекается клиентом по ШК.

--------------------------------------------------------------------------------
3. ОБРАБОТКА ИСКЛЮЧЕНИЙ И ОТКАЗОУСТОЙЧИВОСТЬ
--------------------------------------------------------------------------------
1) Если API 5Post временно недоступен или выдал ошибку:
   - Заказ НЕ ТЕРЯЕТСЯ. В Google Таблицу немедленно записывается строка с пометкой:
     [ВНИМАНИЕ: Сбой создания в 5Post. Оплата получена: CP #... Требуется ручной выпуск накладной].
   - В БД сайта заказ помечается для повторной фоновой отправки (cron-скрипт retry каждые 10 минут).

2) Если покупатель отменил платеж или закрыл шлюз:
   - В базу заказ записывается со статусом «Ожидание оплаты».
   - Заказ в 5Post НЕ создается и в Таблицу отгрузки НЕ уходит до момента поступления подтвержденного платежа.
