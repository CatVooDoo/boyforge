# Промокоды и правила корзины

Ветка: `feature/basket_sdek_promocode`. Пользователь разрешил фиксацию изменений. Работа разделена на коммиты серверного расчёта, администрирования промокодов и интерфейса оформления заказа. Отправку в удалённый репозиторий выполняет пользователь.

## Админка

Вкладка **«Правила корзины»** (`boyforgeadmin/cart_rules.php`) содержит генератор и список промокодов. Можно ввести собственный код (1–32 символа без пробелов), нажать кнопку генерации или оставить поле пустым для генерации сервером. Поддерживаются кириллица и символы; регистр букв не учитывается. Одинаковые коды создать нельзя.

При создании обязательно выбираются активная категория и целая скидка от 1 до 99%. Промокоды многоразовые, без срока действия; один код на заказ. В списке можно отключить или снова включить код. Код удалённой или неактивной категории применить нельзя.

Сохранение и переключение статуса требуют авторизации администратора и CSRF-токена. Коды генерируются криптографическим генератором, уникальность обеспечивается БД.

## Оформление заказа

Поле промокода находится в общей форме оформления: при покупке одного товара и при переходе из корзины. Кнопка «Применить» показывает скидку и итог; кнопка «Убрать» возвращает исходную сумму. Если ввести код и сразу нажать оплату, он сначала проверяется. Ошибочный код необходимо исправить или убрать.

Скидка применяется только к товарам выбранной категории, включая каждую штуку одной позиции. Остальные товары и доставка не получают скидку. Например: два худи по 4 900 ₽, футболка 3 200 ₽, доставка 550 ₽. Код на худи со скидкой 10% даёт скидку 980 ₽; к оплате — 12 570 ₽. Стоимость доставки остаётся 550 ₽. Для СДЭК расчёт тарифа использует исходную стоимость товаров.

`includes/checkout_pricing.php` выполняет одинаковый расчёт для предварительной проверки (`api/promo-validate.php`) и создания платежа (`api/yookassa/create.php`). Цены, категория, доступность, статус промокода и процент берутся из БД; присланные покупателем цена и сумма скидки не используются.

## Заказы и чеки

В заказе сохраняются `promo_code`, `discount_amount` и снимок позиций с ценами после скидки. Для подходящих позиций дополнительно сохраняются `original_price` и `discount_percent`. Скидка округляется до копеек за одну физическую единицу товара.

Платёж и чек предоплаты используют цены после скидки. Закрывающий чек по-прежнему содержит отдельную позицию с DataMatrix на каждую физическую вещь и отдельную немаркированную строку доставки. Формат и поля маркировки не изменялись. Возврат использует сохранённые оплаченные цены, независимо от последующего отключения промокода. Промокод и сумма скидки отображаются в админке, письме покупателю и на странице результата оплаты.

## Подготовка БД

После предыдущих миграций корзины и СДЭК можно выполнить `migrations/20261030_promocodes.sql` **один раз**, либо сначала открыть админку: `ensurePromoSchema()` автоматически создаёт таблицу `promocodes` и недостающие поля заказа. После автоматического создания схемы вручную запускать SQL-миграцию не нужно.

Публичные API схему не меняют. Перед использованием оплаты после выкладки нужно подготовить БД одним из этих способов. Агент не запускал миграцию: доступ к Docker и локальной БД ограничен окружением.

## Проверки

```sh
php tests/promocodes.php
php tests/basket.php
php tests/cdek.php
node tests/promocode-single-checkout.cjs
node tests/basket-checkout.cjs --promo
node tests/basket-checkout.cjs
node tests/basket-checkout.cjs --unconfirmed
node tests/basket-regressions.cjs
node tests/checkout.cjs
```

Проверены смешанные категории, количество, округление до копеек, подмена клиентских сумм, отключение кода и категории, несовпадающая категория, удаление кода в интерфейсе, ответы не по порядку и сохранение стоимости доставки. Проверки чеков и возвратов выполняются без запросов к платёжным сервисам. Синтаксис изменённых PHP/JS-файлов проверен; реальная БД, браузерная проверка и платежи агентом не запускались.
